# 辦公室滑椅甩尾大賽 — Scroll World Landing Page

滑動捲軸 = 推動一台鏡頭。從深夜辦公室一路飛到頒獎台，**全程一鏡到底、沒有任何剪接點**。
畫面是預先算好的影片，捲軸只控制播放時間（Apple 產品頁的同款技法）。

## 怎麼看

必須用 **HTTP 伺服器**開啟，不能直接用 `file://` 雙擊：

```bash
cd chairdrift
python3 -m http.server 8080
# 瀏覽器打開 http://localhost:8080
```

（引擎會把每支影片抓成 Blob 再播，所以不依賴伺服器支援 byte-range；但 `file://` 會擋住 fetch。）

## 製作方式（給之後要改的人）

- 美術：Higgsfield `gpt_image_2`，6 張場景圖共用同一段 style preamble（黑底／紅青霓虹／濕地反光／紅白護欄），這是整個世界看起來像同一個地方的原因。
- 鏡頭：Higgsfield `seedance_2_0`，**架構 A（連續前進單鏡頭）**。第 0 段從場景圖起拍，之後每一段都以**前一段實際算出來的影格**當 `start_image`，且刻意不給 `end_image`（給了會逼鏡頭往後拉，那是接縫抖動的頭號原因）。
- 接縫：每段修剪到第 118 影格，正好是餵給下一段的那張影格。實測相鄰接縫的平均 RGB 差在 ±2/255 以內，再加上引擎 0.08 的交叉溶接，肉眼看不出接點。
- 編碼：原生解析度、crf 20、GOP 8。不要為了 scrub 順暢去降畫質或改 all-intra——順不順取決於 seekability，引擎已用 Blob 解決。

## 已知限制

- **手機版是裁切版，不是原生直式重算。** 目前的 `-m.mp4` 是把 16:9 置中裁成 9:16。因為六幕都是走廊透視、主體本來就在正中央，裁切後仍然完整。若要更好，可以再花約 135 credits 用同樣手法重算一條原生 9:16 影片鏈。
- 影片每段 5 秒、共 29.6 秒；想要更慢的節奏，調 `index.html` 裡每幕的 `scroll`（捲軸距離）與 `linger`（鏡頭中段停留）即可，不用重算影片。
- 低階手機在快速甩動捲軸時仍可能掉格。真的卡，把 `-m.mp4` 的 GOP 再壓到 `-g 2`。
